# 画面遮挡功能审查与修复记录

审查日期：2026-10-09。此记录取代初次实施报告中的完成度估计、旧日期和未经核实的安全及性能保证。用户操作以 [MOSAIC_FEATURE.md](MOSAIC_FEATURE.md) 为准。

## 已核实并修复的问题

| 问题 | 修复后的行为 |
| --- | --- |
| 前端独立保存启用状态与区域，会把父组件开关或配置重置为旧值 | 编辑器由 Semi Form 的配置对象驱动 |
| 直接修改隐藏输入框，表单保存仍可能使用旧配置 | 使用正式自定义字段保存对象，提交到 `override.mosaic_config` |
| 反向拖拽不断移动起点，导致矩形缩小或错位 | 固定拖拽起点，归一化计算并限制画面边界 |
| 高级 JSON 与可视化配置脱节 | 双向同步，校验结构、坐标、强度、颜色和区域数量 |
| 插件解析或执行失败仍可能恢复原片上传 | 遮挡请求失败时保留隔离原片，禁止回退上传 |
| 仅修改事件路径，未可靠隔离实际文件；Noop 绕过处理 | 从落盘命名开始保留未遮挡标记，Noop 也处理完成分段 |
| 多区域滤镜连接、微小区域和奇数坐标影响实际覆盖 | 顺序连接滤镜，限制缩放最小尺寸并向外覆盖像素边界 |
| 转码后工作台路径与旧索引可能指向原片或旧字节偏移 | 等待写入屏障后更新分段、文件列表和索引 |
| 工作台快速/精确切片可能读取尚未遮挡的来源 | 切片规划拒绝带未遮挡标记的原片，处理成功后使用正式输出 |
| 边录边传会在遮挡之前发送数据 | 启用遮挡时拒绝 sync-downloader 路径 |

原文把前端字段名列为必改项，但实际 `OverrideModal` 会将顶层的非实体表单字段移入 `override`。因此 `field="mosaic_config"` 本来就是正确路径，问题出在状态与表单序列化方式。

## 当前实现边界

处理的是已经关闭的磁盘分段，直播预览与录制中的文件仍为原始画面。隔离标记防止项目上传路径误用原片，不代表整个磁盘或实时预览已经经过遮挡。马赛克与模糊也不保证不可辨认。

需要含 libx264 的 FFmpeg；最多 32 个区域，转码任务在本进程内串行执行。GPU 加速、实时效果预览、进度展示、历史录像自动追溯处理尚未实现。不要根据旧文档中的 CPU、耗时或 GPU 提升估计规划容量。

- `cargo test -p biliup-cli --lib mosaic_pending_recordings`：快速/精确切片来源拦截回归通过，涵盖新旧原片标记及录制中的 `.part`。
- `cargo check -p biliup-cli`：完成针对性编译检查；最终多功能整合后的验证由主代理继续执行。
- `node --test app/lib/mosaic-config.test.cjs`：通过对象序列化、删除覆写、非法配置、反向拖拽与越界限制测试。

这些验证覆盖局部实现和本地 FFmpeg 处理，不能代替真实房间长时间录制、真实 B 站投稿以及所有操作系统的完整验收。后续待核查事项见 [CHECKLIST.md](CHECKLIST.md)。

## 2026-10-09 第二轮实际录制验证

- 斗鱼 10035066 的完整浏览器 Cookie 导致网页播放接口返回 403，随后 App 回退只返回低档画质。播放密钥和播放请求只发送登录字段后，正式程序录制到 3840×2160、60 fps。
- 马赛克编辑器改为当前直播关键帧 JPEG 上的矩形圈选；录制时复用缓存 GOP，抓帧失败显示明确状态，不用封面或黑色示意图代替。
- 分段时长支持预设和自定义（时:分:秒、分:秒、纯秒），主播可明确继承或关闭；主库与 Fleet 升级清理旧的 null 占位值。
- 碎片过滤曾在遮挡前丢弃一分钟小分段。现在必要遮挡先执行，再按原始大小过滤，引用保留的输出也已遮挡。

实际测试在独立临时数据库和目录中运行，没有 B 站投稿：5 个 4K60 分段全部遮挡完成，12 秒设置在关键帧边界生成约 12.53 秒正常段，未处理原片剩余 0。直播帧 API 返回 1920×1080 当前游戏画面；同帧对照确认保存的矩形区域出现马赛克。全局 `7:30`、主播 `00:07:30.5`、显式关闭和撤销覆盖均通过真实 HTTP 保存／重载验证。

最终验证：CLI 全套 1013 项通过、0 失败、3 项原有忽略；核心库 216 项通过、0 失败、5 项原有忽略；25 项前端逻辑测试通过；生产前端构建、完整 TypeScript 与相关 ESLint 通过。浏览器工具的安全策略检查不可用，因此没有声称完成自动化浏览器点击验收；实际抓帧、录制、输出图像和配置 API 已验证。
