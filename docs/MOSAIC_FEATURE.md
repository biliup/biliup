# 画面遮挡功能使用指南

更新日期：2026-10-09。本指南以本次源码审查和修复后的行为为准，取代初次实施文档中的完成度估计与未核实保证。审查记录见 [IMPLEMENTATION_COMPLETE.md](IMPLEMENTATION_COMPLETE.md)。

## 功能范围

画面遮挡在**录制分段写入磁盘并关闭后**使用 FFmpeg 转码，对指定矩形应用马赛克、模糊或纯色，再交给原有分段处理和上传流程。选择 `Noop` 上传器或没有投稿模板时，完成分段仍会经过遮挡处理。

**直播预览、浏览器直连、录制中的 `.part` 文件，以及处理中或处理失败的隔离原片仍可能包含原始画面。** 本功能不是实时隐私过滤器，不应将这些入口或文件当作已遮挡产物。马赛克和模糊也不保证无法辨认或还原；需要完整覆盖某区域时可使用纯色。

当前不兼容 `sync-downloader` 边录边传。它会在磁盘分段处理之前发送视频数据，启用遮挡时程序会拒绝启动该路径。请使用支持落盘分段的下载器，例如 mesio、stream-gears 或 ffmpeg。

## 配置方法

1. 在左侧菜单进入「直播管理」，找到已添加的主播，点击卡片底部或列表操作栏的 **「画面遮挡」**，抽屉会直接展开「画面遮挡（实验性）」。原有扳手图标「配置覆写」中也保留这一面板。
2. 打开面板后，程序会抓取该直播间的当前直播画面。确认画面后启用开关，按住鼠标左键或触屏拖拽圈选矩形区域；从任意方向拖拽都可以。
3. 在表格中选择效果、调整强度或纯色颜色；不需要的区域可以删除。
4. 保存。配置用于后续分段处理；已经产生的录像不会自动追溯修改。需要避免当前录制场次继续沿用旧状态时，停止录制后重新开始。

圈选时使用一张固定的真实直播截帧，避免画面移动影响定位；点击「刷新画面」可重新抓取，不会清除已配置的区域。抓帧失败、未开播或暂不可用时会显示状态和重试入口，不能在空白画布或封面上新增区域；已有配置仍保留。画面展示原始直播内容及区域标记，不提供 FFmpeg 最终遮挡效果预览。

入口沿用主播配置覆写的 `streamer.hooks` 权限：默认只有超级管理员可用，未启用 Web 鉴权时视为超级管理员。操作员和只读观察者不会显示这个入口。标有「托管」的 Fleet 房间在节点端只读，需要由控制面修改。

如果界面仍只有扳手图标，可点击它再展开「画面遮挡（实验性）」。如果扳手内也没有该面板，请确认运行的是包含此功能的新版本。自行从源码构建时，先运行 `npm run build` 更新 `out/`。本项目默认的 debug 构建会从磁盘读取 `out/`，更新前端后通常强制刷新浏览器即可；发布构建将页面嵌入 Rust 二进制，需要随后重新编译并启动程序。后端源码改动也需要重新编译并重启。

坐标按实际画面百分比保存，适配不同分辨率。编辑器跟随截帧的实际宽高比例，包括 4:3、超宽或竖屏视频，不添加黑边；窗口或抽屉尺寸变化不会改变区域位置。每个区域的宽高至少为画面的 1%，最多 32 个区域。主播更改画面布局后，可重新抓帧并核对区域，最终位置也应在实际输出上确认。

| 效果 | 配置 |
| --- | --- |
| 马赛克 | 块大小为 4–64 的整数 |
| 模糊 | 强度为 1–100 的整数 |
| 纯色 | `#RRGGBB` 颜色，默认黑色 |

配置对象保存在主播的 `override.mosaic_config` 中，区域字段使用 `effectType`。没有主播覆写时跟随全局 `mosaic_config`；显式保存 `enabled: false` 可关闭该主播的遮挡。高级 JSON 与可视化编辑器同步，保存时校验格式、边界、强度和颜色。

## 依赖与处理流程

需要安装含 `libx264` 编码器及相应滤镜的 FFmpeg。程序复用已有 FFmpeg 路径配置。视频转为 H.264，音频尽量直接复制；当前输出支持 FLV、TS、MP4/M4S、MKV、MOV 和 AVI，音频与目标容器不兼容时会报错并保留原片。

处理顺序为：

```text
录制原始分段（文件名带 .unmasked 标记）
  → 分段关闭并完成工作台写入
  → FFmpeg 生成临时遮挡视频
  → 成功后发布正式文件并更新文件列表、分段路径和索引
  → 原有 segment_processor
  → 上传，或 Noop 的本地后处理
```

新录制可能使用 `name.unmasked.flv` / `name.unmasked.flv.part`；旧路径的 `name.flv.unmasked` 也会识别。碎片过滤在遮挡成功后按原始分段大小执行：小于阈值的分段仍不投稿；被工作台引用而保留的分段也会完成遮挡。短分段应同时调整碎片过滤阈值，避免录完又被过滤。配置无效、缺少区域、FFmpeg 失败或超时不会回退上传原片。原片保持隔离，带未遮挡标记的文件被自动与手动上传路径拦截，工作台也拒绝从这些待处理来源导出切片。不要手动移除标记后将原片误当成遮挡成功的视频。

FFmpeg 处理在本进程内一次运行一个任务，其他分段排队等待。分辨率探测超时为 30 秒，单个转码任务超时为 1 小时。处理耗时和临时磁盘占用随分段长度、分辨率、区域数量及机器性能变化，没有固定的「1–5 分钟」保证。

## 故障排查

- 开启后无法录制：检查是否选择了 `sync-downloader`。
- 保存时报错：至少绘制一个区域，检查高级 JSON、坐标边界、整数强度和颜色格式。
- FFmpeg 处理失败：检查程序配置的 FFmpeg 路径、`libx264`、输入容器和音频兼容性、磁盘空间及日志。失败原片仍带未遮挡标记。
- 工作台画面与输出不同：录制中和处理中的预览可能仍为原片，应等待分段处理成功后检查正式输出。
- CPU 负载或积压较高：减少区域或降低录制分辨率，并合理设置分段时长。4K60 的转码可能慢于实时，缩短分段不会增加总处理能力。当前未实现 GPU 编码与 FFmpeg 进度展示。

## 自定义录制分段时长

在「空间配置 → 全局设置」或主播「配置覆写 → 下载设置」的「视频分段时长」中选择「自定义时长…」，输入 `00:07:30`、`7:30` 或 `450`，均表示每 7 分 30 秒分一段，也支持小数秒。主播可以明确选择「跟随全局设置」或「不按时长分段」。分段会在适合的关键帧边界关闭，实际长度可能稍长于设定。短分段需要同时检查碎片过滤阈值。
